Keep epics and tasks in a durable conversation ledger, with open work visible in the prompt.

The `plan` tool creates epics (`E1`) and tasks (`E1.1`), updates them, adds timestamped task notes, and reads full plans with `show`. Epic bodies hold Request, Selected approach, Intent, Scope (in/out), binary Acceptance criteria, Implementation, Verification, and Risks. Task descriptions hold Outcome, Scope, Non-goals, Files, Acceptance criteria with a verification command, and Constraints.

`ultimate.plan` is an exported conversation document with rewindable history and `asOf` forks (Pi Durable requires rewindable history for historical forks, and stores the fork mode with each document, so it cannot change). A lineage branch (one with a `lineage.branch` document) starts with an empty plan: a `beforeInput` hook empties the forked copy in the commit that places its first input, so its first request never sees the inherited plan. The `plan.started` marker records that first run; a branch that answered before it had the marker keeps its plan. Subagents read their coordinator's ledger anyway. Each call first saves a receipt identity via `api.memo` (namespaced by codemode for nested calls), then commits its receipt alongside the edit in a task-scoped document and saves the result via `api.memo`. Calls sharing an outer task ID have distinct receipts; interrupted replays cannot duplicate tasks or notes. Unknown keys, invalid statuses, and fields meant for the other kind of record are errors. Dependencies must name existing tasks. Notes belong to tasks; epics and tasks both accept evidence or conclusions in `verdict`. `body` remains epic-only.

The `plan` section lists non-done epics and their tasks, including dependencies and linked child conversation numbers, without plan bodies. Children resolve conversation ownership up to the root coordinator: `show` reads that coordinator's ledger, while mutations fail with “Only conversation N edits this plan; report to it instead”. The coordinator links a child explicitly with `update {key, child}`. The compact prompt section remains local to the conversation.

`web.tsx` puts the plan beside the conversation instead of in the Documents tab: on the Agent surface an `overlay` pill floats at the top right of the prompt. On a coordinator it shows the newest open epic's progress (`E2 · 1/4 done`, `+N` for more open epics), or for an epic the coordinator works without tasks its status and criteria count (`E1 · planning · 6 criteria`); on a linked worker it shows its `TaskChip`, the task title and `↑ #<coordinator>`, which shows the coordinator with that task open. Clicking the pill expands a card (durable UI state `plan.panel`) with the plan, live: a worker reads its coordinator's `ultimate.plan` on its own event stream and sees its own task highlighted and expanded. Open epics come first, newest first, each with its plan folded below, the verdict when there is one, and its tasks; done epics fold into one row. `body.tsx` splits a body at the labels the tool asks for (`Request:`, `Scope in:`, `## Risks`…) for display only: each section gets a small label, and Acceptance criteria become a quiet checklist (met once the epic is done). An epic without tasks shows that checklist in place of the tasks, labelled "worked directly", or "Worked directly by the coordinator." when it has none. Plan text renders as written: `<tags>` outside code stay text instead of being dropped as HTML, single newlines break lines, and Streamdown's streaming repair (which closed a lone `*`) is off. Each task shows its key, title, status, role, and dependencies (done ones green), the linked child as "open #id" with a dot while it works, the verdict when present, and the last note, with the description and all notes on click; hovering shows "link", which copies `?conversation=<coordinator>&task=<key>`. A task whose child has a worktree isolate shows its branch, its state (`Landed <sha>` once landed), and commits ahead, read with the `workspaces` `info` action; it refetches when the child or parent settles and on window focus. The panel follows durable UI state `plan.open`: when it names the shown conversation, the panel opens, that task (or epic) expands and scrolls into view, and the request clears. A `?task=` in the page URL sets it once on load and leaves `?conversation=` to the shell. `plan` calls render as a compact card naming the action and key (a task's `TaskChip`, or an epic key that opens the panel there), with the plan, task, verdict, or note text below.

Each mutation also rewrites the coordinator's entries in `ultimate.plan.tasks`, an exported document on the root conversation mapping every linked child conversation id to `{ coordinator, epic, key, title, status }`, in the same commit. Relinking a task drops its previous child; a child linked by a second task moves to it. A child that newly gets a task, or whose task is renamed, takes the task title as its conversation title, so the header, sidebar and Task Graph show the task instead of the start prompt; a later manual rename stays until the task title changes. `chip.tsx` is for other web facets: `useTaskIndex()` and `useTaskOf(id)` read the index, `TaskChip` (a `span` with the button role, so it fits inside row buttons) shows a task key with its status dot (hover for coordinator, title and status), and clicking it, like `useOpenTask()`, shows the coordinator and sets durable UI state `plan.open` to `{ conversation, key }`. It also owns the status icons and colours `web.tsx` uses.
