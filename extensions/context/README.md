What the model saw before a conversation's first input: a quiet header above it names the agent, its model and the estimated token budget, and opens to the agent's definition, the system prompt section by section, the tools with their schemas, and the context injected before the input (a branch's memory brief or tally, a compaction summary, a fork's inherited history), each with its tokens and share.

A later context start (a compaction, a reset) shows its own breakdown under its card. A `pi.system` patch mid-conversation stays a one-line marker, `Reloaded` for an extension reload, `Restarted` for a same-build restart, `system prompt` otherwise, that opens to a diff: each section and tool added, changed or removed, with its token delta and full text; a changed section opens to a line diff of its old and new text. A remove-all patch Pi Durable writes before a reordered re-add folds into that re-add's diff.

The **pinned prompt** sits at the top of a top-level conversation's transcript (`transcript.top`; not in subagents): the same header for the prompt the conversation runs with now. It hides while the start card is on screen and nothing changed. The first prompt it sees becomes the baseline, kept per conversation as `context.seen.<id>` in durable UI state; a later change lights the pin up (`1 section changed · +4`) and opens to the changes since the baseline above the breakdown, and **Dismiss** makes the current prompt the new baseline. The `currentPrompt` action replays the prompt from the conversation's whole model context, since the stream sends only its newest entries, and diffs it against the context at the baseline entry; the pin asks again whenever a new `pi.system` entry streams in.

A response that rebuilt the prompt cache gets a quiet amber line above it: what it wrote fresh, what it still read of the prompt before, and why (a system prompt change, a model switch, an expired cache, a changed earlier context). Other extensions add to it through the `CacheRebuiltDetail` point in `ui.tsx` (`context.cache-rebuilt`): each provider's text for the response's entry and its rebuild shows as one more `· …` part at the end, with an optional tooltip, such as what the rebuild cost.

A branch is a fork of its root; the transcript hides the inherited root history before its own first entry and stops paging there, since the brief the header shows is what the branch actually starts from.

`breakdown.ts` is the pure model (replaying `pi.system` patches from the last context start, estimating tokens with Pi's `estimateTextTokens`: 3.5 characters per token, an image a fixed 4800 characters). `parts.tsx` holds the header, its rows and the diff body; `pinned.tsx` the pin; `server.ts` the action. `web.tsx` renders the header through the core `transcript.start` slot, which the transcript shows above its first row once its whole history is loaded, and renders `pi.system`, `pi.reset` and `pi.compaction` entries. It shows only what entries record as sent to the model; settings, provider headers and secrets are never read.
