One stream of everything Ultimate records: durable events (`host.eventLog`) and the call trace (`host.trace`: service, action, reactor, tool and model calls), merged into one row shape, paged and filtered on the server. The System surface reads it; agents can call it with `ultimate.action('system', 'stream', …)`. Optional; it changes nothing.

Actions (contracts in `refs.ts`):

- `stream { before?, after?, limit?, sources?, kinds?, conversation?, errors?, text? }` → `{ rows, next?, head }`. Rows newest first, at most `limit` (default 200, at most 500). Each row is `{ id, source, at, kind, name, conversation?, trace?, ok, ms?, error?, summary }`: an event has kind `event`, id `e<event id>` and its data as summary; a call has its kind, its id and `caller → callee  args` as summary (arguments as the trace stored them, secrets redacted and tool arguments sealed).
  - Order: events by when they were emitted, calls by when they finished (the trace writes a call when it settles), ties by id.
  - `before: next` pages back; `next` is absent once nothing older matches. `after: head` follows live: the rows recorded since the cursor, newest first, the oldest `limit` of them when more arrived, with a new `head`. Cursors are opaque (`<event id>.<trace position>`), one position per source, so paging never skips or repeats a row; reuse them only with the same filters.
  - Filters: `sources` (`event`, `call`), `kinds` (event names and call kinds together: `['workspaces.landed', 'tool']`), `conversation` (the event's emitting conversation or the call's), `errors` (failed calls only, so no events), `text` (case-insensitive substring of name, caller, callee, arguments, error or event data). Call filters run in SQL on `trace.sqlite`; event filters run while scanning the event log.
- `lanes { since?, until? }` → `{ now, lanes, more? }`: who worked when, for the Agent Lanes timeline. Default window: the last 30 minutes. One lane per conversation with tool or model calls in the window (trace kinds `tool` and `model`), most recently active first, at most 40 (`more` counts the rest). A lane's runs are its calls grouped into stretches split by more than 20 s of quiet, each `{ start, end?, ok, calls, more? }` with at most 200 calls (`{ at, ms, kind, name, ok, trace }`) (`more` counts the newer ones left out). The last run has no `end` while it is open: its last call ended under 20 s ago or the conversation has a live foreground task (the harness task graph); a window ending in the past is never open. `agent`, `model` and `kind` come from the conversation's newest `subagents.started` event when there is one; titles are the browser's to resolve.
  - Hierarchy: `parent` is the conversation that started the lane: the one whose tool call emitted its `subagents.started` (the event's `context.conversationId`), else the event's `parent`, else its owner or the conversation it branched from (`host.conversations()`, for lanes without an event). Each listed lane brings its parent along, one hop up: a parent that did not work in the window is a lane without runs; lanes and parents together stay within the 40. `spawn { call?, at, inferred? }` is the parent's tool call that started it: the one the event's `context.parentCall` ran in, else (`inferred`) the parent's last `subagent`, `branch` or `message` call before the event or the lane's first call. `links` are the `board.sent` messages between listed lanes sent in the window, oldest first, `{ from, to, call?, at, kind: 'message' }`, `call` and `at` the sender's `message` tool call when the event names it.
- `tree { trace }` → `{ calls, events }`: the call tree of one trace, as `stream` rows with `parent` and `children`, and the events emitted in that trace, oldest first.
- `navigated { surface, conversation? }` → `{ recorded }` (user-only): records a `ui.navigated` event with the browser's device label, unless it repeats the last one. The facet's overlay calls it when the surface on screen, or Agent's open conversation, has stayed for a second and differs from what that tab last reported; clicks, scrolls and panels are not reported.
- `polls` → `{ polls }`: the poll counter from `host.trace.polls()`, the successful action and service calls the trace counted instead of writing because they repeated one written within the last minute, `{ name, count, since }` most first.

The **System** surface (⌘K "Open System", or "System ↗" in the Activity panel) shows both. Other extensions add tabs beside **Agents** through the `system.tab` point in `ui.tsx` (Wire does); the open tab is kept in UI state `ext.system.tab`. **Agent Lanes** on top:
one row per lane with its agent's mark, model and state (running, waits on you, awaiting @ultimate, done, failed, idle: the sidebar's conversation state) and its runs as blocks on a
30 m / 2 h / 24 h timeline, labelled by their main tool, with calls as ticks (failed ones red). Lanes form a tree:
children indented under the lane that started them, with a dotted guide, in the order they started; a parent with more
than three finished children folds them into a "+N finished" row (unfolding is remembered in the browser). A dotted
line runs from the spawning call (a dot) on the parent's row to the child's first block, fainter when inferred.
Hovering a lane, or opening one of its runs, lights its chain (ancestors and descendants) and dims the rest, and shows
its messages as faint vertical lines between sender and recipient. On a phone only the indentation and guides show. A block opens its calls
and a call its trace tree; a lane's name opens the conversation, its filter button narrows the stream to it. Below,
**All events**: the stream with source chips, errors only, a conversation filter and text, each row opening its trace
tree, older pages loading at the end. Both poll every 2 s while the surface is on screen.

Uses two read methods of the core: `host.trace.page()` (calls by write position with the filters above and a `since`/`until` start-time window) and `host.eventLog.recent({ before, order })`.
