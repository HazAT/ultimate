Look at Ultimate's UI and drive fresh headless Chromium pages with `screenshot` and `browser`. After UI changes, inspect the returned image rather than assuming the page renders.

Install Chromium separately; playwright-core does not download browsers. Resolution checks `ULTIMATE_CHROMIUM`, then the platform's system browsers (on macOS Google Chrome, Chromium and Chrome for Testing in `/Applications`; on Linux `/usr/bin/chromium` and `/usr/bin/google-chrome-stable`), then Playwright's `chromium-*` installs, newest first (`~/Library/Caches/ms-playwright` on macOS, `~/.cache/ms-playwright` on Linux). A browser is launched lazily and closed when the host shuts down. Each call has its own isolated context, closed on completion or cancellation.

No call can hang: loading, each step (including `eval`, which Playwright never times out) and the capture each time out after 30 s (`timeoutMs` overrides it), and a whole call after four such limits plus its explicit waits. A timed-out step fails the call with a `TimeoutError` on its `Step n:` line. Closing a context is bounded too; a context that will not close (a wedged renderer) closes the shared browser, so the next call launches a fresh one.

`screenshot` accepts url, path, viewport dimensions (1440 × 900 by default), selector, fullPage, waitMs (1500 by default) and light/dark theme. A page of Ultimate's own UI is detached from the shared durable UI state: it reads it once at load, then its `?conversation=`, panels and clicks stay its own, so a driven page never moves the user's tabs. For own-UI screenshots, theme initializes this isolated browser's `ultimate.theme` localStorage preference before navigation. Other URLs receive only the browser color-scheme preference. `url` is the page to load; a relative one such as `/` (which opens @ultimate, as every page without `?conversation=` does) or `/?conversation=<id>` resolves against this UI. `path` is where the full-resolution PNG is saved: it must end in `.png`, resolves against the conversation's cwd (its worktree in an isolated workspace), and missing parent directories are created. Without it the PNG goes to `$ULTIMATE_HOME/screenshots`. Either way the result names the absolute file; Pi's `resizeImage` returns compact PNG or JPEG images capped at 1600 pixels on the longest side, using its default quality and byte limit. Resized images include a dimension note for mapping coordinates to the original. If an image cannot fit the limit, the tool returns the PNG path without an inline image. Loading console and page errors accompany the title and PNG path.

`browser` accepts the same url and path, click/fill/press/wait/eval/send/until steps and an optional final screenshot (default true). Every page it drives is marked `ultimate.driven`, so an Ultimate UI, this one or a preview, installs `window.ultimate` (`web/src/sdk/test-hook.ts`) from its own stream: `send` submits a prompt to the shown conversation (or `conversation`), and `until` resolves on the store change that makes its condition hold: `'idle'` (that conversation's sent turn ran and is no longer busy; a turn too short to show busy counts by its answer time), `'quiet'` (no conversation busy), `{entry: kind}` (a new entry of that kind) or `{event: name, where}` (a durable event from the root's feed whose data matches `where`). After a `send`, entries and events count only from it. `until` gets its own budget, 5 min unless `timeoutMs`, and on timeout names what was still busy or what arrived instead. A page without the hook fails the step with that reason.

Click only what you are testing. Set up everything else (model, thinking, Play/Pause, abort, compact) through `window.ultimate.api`, the page's own SDK client (`web/src/sdk/api.ts`), in one `eval` step, or curl the preview's HTTP API; then wait with `until`, never a fixed `wait <ms>`. Switching conversation 2 to another model: `{eval: "window.ultimate.api.configure({model: {provider: 'openai-codex', modelId: 'gpt-6.1-sol'}}, 2)"}`. Likewise `api.configure({thinkingLevel: 'high'}, id)`, `api.abort(id)`, `api.compact(undefined, id)` and `api.action({extension: 'pause', name: 'play'}, null)` for any extension action. In a preview, standing agents (@ultimate, @lander) stay on `instance.model`; a model switch sticks on a conversation you create (`api.createConversation()`).

`where` compares fields of the event's data, so a key the event does not carry never matches and the step waits out its budget. Events carry ids and counts, never text: `user.input` is `{conversation, kind: 'prompt'|'steer'|'follow-up'|'answer'|'dismiss'|'review', entry?, submission?, message?, length}`, `board.sent` `{message, from, to, reply, steer}`, `subagents.started` `{id, agent, model?, thinking?, parent?, kind: 'child'|'standing'|'branch'}`, `coding-tools.committed` `{conversation, sha, parents, repo, worktree?, branch?, subject, rewrittenFrom?}`, `workspaces.check` `{submission, command, result, ms}` and `workspaces.landed` `{conversationId, sha, base, target, lander, title, commits, paths, …}`; every other event's fields are in the `defineEvent` of its extension's `refs.ts` (or `shared/events.ts`). Entry kinds are what `window.ultimate.state()` lists (`pi.user`, `pi.assistant`, `pi.tool-result`, …); tool calls live inside `pi.assistant`, there is no `pi.toolCall` entry. JavaScript eval runs inside the page. Calls stream progress; screenshot is replay-safe, browser is not because interactions may submit prompts. Both are automatically available in codemode's `tools`; use `const shot = await tools.screenshot({}); if (shot.image) image(shot.image)` to display its image. Structured nested results include title, PNG file path, outcomes, and an image data URI.

`web.tsx` renders `screenshot` as a thumbnail that opens full size, with the page title, PNG path, and loading errors, and `browser` as its steps with an outcome each (✓, ✗ with the error, the value an `eval` returned) and the final screenshot.
