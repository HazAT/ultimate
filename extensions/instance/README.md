Run an on-demand second Ultimate to test core changes before restarting the shared host, or, in another project, to check that project's `.ultimate/` extensions. Start it, check its API and UI, then stop it. Creating a conversation never starts a preview automatically.

`instance` supports start, stop, logs and list. An isolated caller previews its ready workspace; `start {subagent: <child id>}` selects an owned child's workspace. A shared caller previews the host source and project. When the project is Ultimate itself, a workspace preview runs the workspace's own source and requires `server/main.ts` and `node_modules`; run `pnpm install` first. In any other project the host's Ultimate runs with the workspace as its project, and the prompt says the preview is not the project's own app. Previews do not prevent landing or removal.

A preview of a git project lands on its own branch, `ultimate/<hash>-preview` (the hash of its home, like its workspace branches), created at the project's tip, and never pushes, whatever `lander.push` says: its workspaces target that branch (`ULTIMATE_PREVIEW_BRANCH`). Its git processes also include `<home>/preview.gitconfig` in the previewed repository only (`includeIf gitdir:`): every push there is rewritten to a transport that does not exist, and a reference-transaction hook refuses changes to any branch or tag outside the preview's own `ultimate/<hash>-` branches. Stop and the sweep delete those branches with the home.

Start uses a temporary home unless a separate home is supplied. A preview cannot share the host's home or another running preview's home. The child binds to localhost port zero; the tool reads its `Ultimate: <URL>` stdout line and checks `/api/models`. Startup has a 60-second deadline, with the output tail included in errors.

A preview runs `server/main.ts` without the supervisor, so it cannot restart: verify restart and chapter-switch flows on a supervised scratch server instead (`ULTIMATE_HOME=$H ULTIMATE_USER_HOME=$H/user pnpm start --port <free port> --no-open` on a fresh `H=$(mktemp -d)`, see `docs/running.md`), and delete its home afterwards. A state no server can reach is reported as unverified, never faked by injecting entries.

A preview runs every agent on one model and spends tokens: seed it by prompting it as a user would. The `instance.model` setting (`"provider/id"`, project over user, default `openai-codex/gpt-6.1-sol`) reaches the preview as `ULTIMATE_MODEL`. There it wins over everything else: the root's default model, agent definition pins (@ultimate, coordinators, the lander, subagents, automation runs) and `summaryModel`; thinking levels are clamped to what it supports, and an `openai-codex/` or `openai/` model runs on the fast tier. `"instance": { "model": null }` turns the override off, so a preview runs the configured models. `instance start` with `model` overrides the setting for that preview only: a `provider/id`, or `null` for the configured models. Provider logins are read from `~/.pi/agent`, never copied. No state is copied; a workspace preview follows its main checkout's project decision, as every linked worktree does. Each preview keeps its own SQLite storage and Vite cache.

Logs returns the last 200 lines; list shows running instances. At most three may run, including starts in progress; shutdown stops them all. Logs are available until stop. After the child exits, stop and host shutdown remove tool-created temporary homes, their registered Git worktrees (including dirty preview scratch) and workspace branches named with that preview home's hash. Any foreign branch checked out in a preview is preserved. An explicitly supplied `home` is preserved, including its worktrees and branches, for reuse or inspection.

On open, a background sweep removes dead `ultimate-instance-*` homes in the system temporary directory; failures become notices. Every host sweeps that shared directory, so a sweep runs only while it holds `ultimate-preview-sweep.lock.db` there and is skipped while another sweep does. It probes exclusive transactions on both `storage.lock.db` and `ultimate.lock.db`, holding them through cleanup, and preserves any home with a live PID sidecar. A parent PID lease protects a preview from publication until stop, including startup before the child acquires storage. SQLite locks protect live owners even when a sidecar is missing; malformed sidecars fail closed. No live preview is signalled or removed, including previews of another host. The tool is not replay-safe. Returned URLs work with screenshot or browser.

Each instance records the conversation it previews (or that started it in the shared checkout). The `list` action (`POST /api/extensions/instance/actions/list`) returns the ones that served their UI as `{ id, url, conversationId?, label?, ref?, running, tailnet? }`: running ones, and those that exited or were stopped (`running: false`). Stopped ones are kept per port in the home's `previews.json`, the last 50, so they survive the restart that stops every preview; a start that never became ready is not among them.

## Previews of a commit, started by the user

Two user-only actions (`userActions`: the UI calls them, codemode refuses them) let an extension offer a preview of any commit of the project, such as a Preview button on a pull request:

- `start { ref, label }` previews `ref`, a commit or ref name that is already local (fetch a PR head first; `start` never fetches), listed as `label` (at most 80 characters, such as `PR #200`). It checks the commit out on the preview's own `ultimate/<hash>-checkout` branch in `<home>/checkouts/commit` and runs it like a workspace preview: in another project the host's Ultimate with that checkout as its project, in Ultimate itself the commit's own code after the project's `isolates.worktree.setup` (`pnpm install`) ran there. The push guard, the shared limit of three previews and the `instance.model` setting apply as for any preview. It resolves once the preview serves its UI, with `{ id, url, label, ref, running: true }` (`ref` the full commit), and runs on even if the page that asked leaves. It belongs to no conversation, so concluding one never stops it.
- `stop { id }` stops a preview `start` started and returns `null`. Stop, host shutdown and the sweep remove its checkout, its branches and its home.

Such a preview stops by itself after an hour with no page open: every minute the host asks its `GET /api/pages` (the open pages, each holding one event stream, the frame and tailnet tabs included); one that exited stops at the next check. A commit from before `/api/pages` counts as idle, so it stops an hour after its start.

**Only preview commits you trust.** A preview runs the commit's code as you: its `.ultimate/` extensions and agents run with the main checkout's project decision, and in Ultimate itself its server code runs, all with your home linked in (logins, `~/.ssh`, `gh`). The push guard stops `git push` only; `gh`, `ssh` and network calls still act as you. A pull-requests extension should offer Preview only for collaborators' PRs, never for an outside contributor's.

Code inside any preview can tell where it runs: `ULTIMATE_INSTANCE_OWNER` (the host's pid) is set in every preview and never in a host, as `update` and `sync` already use it; an extension that acts on the outside world (GitHub, mail, deploys) should turn those actions off when it is set. `ULTIMATE_PREVIEW_BRANCH` is missing in previews of a project without Git, so it is not a marker. `tailnet` is `https://<dns>:<port>` for a running preview that publishes itself there: a preview's own `tailscale` extension records its HTTPS port in `~/.ultimate/tailscale.json` under an owner token starting with its pid, and the DNS name is the host's (the `tailscale` service's status). Without the host's tailscale ready, or that entry, it is absent.

`web.tsx` renders instance cards with URL, pid and home, plus collapsible logs; the URL behaves as a preview link, and the card's dot and status turn grey once the preview is gone. It asks for `list` every 5 s, on every page, for the switcher (running previews only) and preview links. While previews run, a chip after the title bar's project chip is the switcher (`2 previews ▾`, just `▾` on phones, through `titlebar.left`), leaving `titlebar.project` to other extensions; it lists "This project" and each preview as `#<conversation> <title>  :<port>` (or its `label`, for one the user started); opening it asks again. Choosing a preview shows its whole UI in a frame below the title bar, which the embedded page leaves out, and the chip names it (`● #12 · :41234 ▾`). "This project", another surface, or the preview stopping returns to this project; a reload does too. Pages opened from elsewhere than loopback, such as the tailnet, show no switcher, since the frame needs loopback URLs.

Its `link` renderer turns Markdown links to loopback ports into chips: a dot, then the link text. A link to a running preview has a brand dot and shows that preview in the frame at the link's path and query, without the external-link dialog. A link to a preview that no longer runs has a grey dot, does nothing, and says "Not running" on hover. A link to a loopback port this server never ran a preview on, such as a dev server, stays a normal link. A link to this server's own port opens in place, at the link's path and query. On a page opened from elsewhere, a running preview with a `tailnet` address opens it in a new tab, since that page has no switcher to return from a frame; one without says "Only on this machine". Other links keep the default.
